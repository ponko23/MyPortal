# 共通基盤 - ドキュメント

## 共通基盤の目的

共通基盤は、MyPortal の複数のアプリから利用する再利用可能な機能とロジックを集約したものです。

各アプリが独立しながらも、共通の機能を効率的に利用できる基盤を提供することが目的です。

## 共通基盤の責務

共通基盤には、少なくとも以下のような機能を含める可能性があります。

- **UI コンポーネント**: 複数アプリで共有される UI 部品
- **テーマ**: デザイン・スタイル管理
- **State 管理**: アプリケーション状態管理
- **Action**: ユーザー操作やイベント処理
- **Validation**: 入力値検証（UI フレームワーク非依存）
- **Persistence**: データ永続化層の抽象化
- **ローカルストレージ**: SQLite / OPFS へのアクセス
- **その他**: アプリ間で共通化可能なアプリケーションロジック

### 責務に関する重要な原則
- **先行実装の回避**: 現時点で必要性が確認されていない機能まで先行して実装・抽象化しないこと

## 設計上の基本方針

### 機能単位での分離

共通基盤は機能単位で分離することを基本方針とします。

```
common/
└─ src/
   ├─ Components/          # UI コンポーネント
   ├─ State/               # 状態管理
   ├─ Validation/          # バリデーション
   ├─ Persistence/         # 永続化層
   └─ ...
```

（実際の構成は、発展に伴って定義されます）

### 複数の DLL への分割

共通基盤の機能は必要に応じて複数の DLL として分割します。

各アプリが共通基盤の全機能を参照することを前提とせず、必要な機能だけを依存関係に追加できる構成を目指します。

**例**:
- `MyPortal.Common.Components` - UI コンポーネント
- `MyPortal.Common.State` - 状態管理
- `MyPortal.Common.Persistence` - 永続化
- など

### UI とアプリケーションロジックの分離

共通基盤では、UI フレームワーク非依存なロジックと UI 固有の実装を明確に分離します。

```
UI Component (Blazor)
    │
    ├─ State         (UI フレームワーク非依存)
    ├─ Action        (UI フレームワーク非依存)
    └─ Validation    (UI フレームワーク非依存)
          │
          ▼
    Application / Domain Logic
          │
          ▼
      Persistence Layer (UI フレームワーク非依存)
```

**アダプターパターンの活用**:
ViewModel は必要に応じて State / Action と UI の DataBinding を仲介するアダプターとして機能しますが、
アプリケーションロジックの主要な配置場所には**しません**。

### Validation の分離

Validation には少なくとも以下の責務があり、これらを明確に分離します。

1. **ドメイン検証**: アプリケーション・ドメイン上の入力値が妥当かを判定する処理
   - UI フレームワークに依存しない場所に配置
   
2. **UI 検証**: UI 上でいつ・どのようにエラーを表示するかの判定
   - UI フレームワークに依存して実装
   - ドメイン検証の結果を利用

**例**: 同じ TextBox であっても、対象となる State によって Validation やAction が異なるため、
UI コンポーネント固有の固定ルールとして実装しないことを基本とします。

## データ永続化の設計方針

### 抽象化層の重要性

UI やアプリケーションロジックから永続化方式を直接参照しない構造を目指します。
これにより、将来的にローカル保存から Google Drive バックアップなどへの拡張が容易になります。

### 初期段階の永続化

```
SQLite
  ↓
OPFS
```

この構成で初期実装を行います。

### データ分離ポリシー

- アプリごとにデータを分離することを基本
- 必要に応じて共通設定などを共有する余地を残す

## 今後の拡張検討事項

以下の機能は現時点の初期実装対象には含めません。ただし、設計時には将来的な拡張を阻害しないよう配慮します。

- Google Drive によるバックアップ
- 複数ユーザー間でのデータ共有
- 認証機能
- バックエンドでのデータ永続化
- Cloudflare などのバックエンド機能

## 共通基盤の利用ガイドライン

### 各アプリが依存する方針

各アプリは、共通基盤から必要な機能だけを参照することを基本とします。

```
appA
  ├─ common.Components
  └─ common.Persistence
     
appB
  ├─ common.Components
  ├─ common.State
  └─ common.Validation
```

このように、アプリごとに異なる依存構成が可能です。

### 機能追加時の検討事項

新しい機能を共通基盤に追加する際は、以下を検討してください。

- **再利用可能性**: 複数のアプリで本当に利用する可能性があるか
- **責務の明確性**: UI フレームワーク非依存な部分と依存する部分が適切に分離できるか
- **抽象化の妥当性**: 実装後に実装の詳細が隠蔽され、複数の実装パターンに対応できるか
