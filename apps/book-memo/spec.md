# book-memo 仕様

## 目的

読みたい本の候補と読んだ本を管理し、いつ読んだか、いつ購入または借りたかを記録する。気になる本や、購入したまま読めていない本についても、購入するかどうかや読まない理由を残せるようにする。

## 想定する利用場面

1. 本を購入して読んだ日付と一言メモを記録する。
2. 図書館で本を借りて読んだ日付と一言メモを記録し、購入するかどうかも記録する。
3. 気になる本を候補として登録し、購入するかどうかを記録する。
4. 購入した本が未読のままになっている理由を記録する。

## 機能要件

| 優先度 | 機能 | 要件 |
| --- | --- | --- |
| 必須 | 一覧画面 | 登録した本を状況にかかわらずタイトル一覧で表示する。状況によるフィルターとソート、詳細画面への移動、新規追加、一括削除を行える。 |
| 必須 | 詳細画面 | ISBN・書影などの書誌情報と、所持形態・状態・購入日・読了日・一言メモなどの個人記録を分けて表示・管理する。 |
| 必須 | 新規登録画面 | 必要情報を入力して本を登録する。ISBNコードが分かる場合は検索し、取得した情報を書誌情報だけに反映する。 |

## 登録情報と入力ルール

### データモデル

データは「書誌情報（本自体の情報）」と「個人の読書記録」に分けて管理する。ISBN検索や検索結果の再取得で書誌情報を更新しても、読書記録は変更しない。

中心データモデルは `src/Models/` に実装する。永続化用の `BookMetadataDto` と `ReadingRecordDto` を分け、画面・アプリケーション用の `BookState` が両方を組み合わせる。

#### 書誌情報（本自体の情報）

| フィールド | 型・必須条件 | 説明 |
| --- | --- | --- |
| `isbn` | string、任意 | ISBNコード。検索・書誌情報の識別に使う。 |
| `title` | string、必須 | 本のタイトル。ISBN検索で取得・更新する。 |
| `authors` | string list、任意 | 著者。ISBN検索で取得・更新する。 |
| `publisher` | string、任意 | 出版社。ISBN検索で取得・更新する。 |
| `publishedOn` | `DateOnly?`、任意 | 出版日。ISBN検索で取得・更新する。 |
| `coverImageUrl` | string、任意 | 書影の参照先。ISBN検索で取得・更新する。 |
| `description` | string、任意 | 本の紹介文など。ISBN検索で取得・更新する。 |

書誌情報はISBN検索結果を反映する領域とする。同じISBNを再検索した場合、検索結果に値がある書誌項目は検索結果で更新し、検索結果に値がない項目は既存値を維持する。別のISBNを検索して書誌情報を差し替える場合は、検索結果で書誌情報全体を置き換え、検索結果にない項目は空にする。いずれの場合も個人の読書記録は変更しない。

#### 個人の読書記録

個人の読書記録は書誌情報を参照し、以下の利用者固有の情報を保持する。ISBN検索による書誌情報の追加・再取得では、これらの値を上書き・初期化しない。

| フィールド | 型・必須条件 | 説明 |
| --- | --- | --- |
| `registeredOn` | `DateOnly`、必須 | 利用者が本を記録に追加した日。初期値は当日。ISBN検索日ではない。 |
| `borrowedOn` | `DateOnly?`、任意 | 借りた日。購入日とは別に保持する。 |
| `purchasedOn` | `DateOnly?`、任意 | 購入した日。借用後に購入しても借用日を残す。 |
| `isPurchaseCandidate` | `bool?`、任意。初期値 `null` | 購入候補かどうか。`null` は未判断、`true` は候補、`false` は候補ではない、の3状態を区別する。所持状況とは独立して設定できる。 |
| `readingStatus` | enum、必須 | 初期値は `Unread`（未読）。登録後は任意のタイミングで変更できる。 |
| `readOn` | `DateOnly?`、任意 | 読了日。読書状態が読了でも入力は必須にしない。 |
| `memo` | string、任意 | 一言メモ。 |
| `unreadReason` | string、任意 | 購入した本を未読のままにしている理由。 |

日付は時刻やタイムゾーンを含まない暦日として扱う。

所持状況は重複して保存せず、日付から導出する。

| `borrowedOn` | `purchasedOn` | 導出する所持状況 |
| --- | --- | --- |
| なし | なし | 未所持 |
| あり | なし | 借用記録あり・未購入 |
| なし | あり | 購入済み |
| あり | あり | 借用後に購入済み |

`isPurchaseCandidate` は所持状況とは独立した任意フラグとする。未所持の本を購入候補として登録する場合は `true` を設定する。購入済みの本にも購入候補フラグを設定できる。

初期リリースでは借用日を1つ記録し、返却日は管理しない。そのため「借用記録あり」は現在借用中であることを意味しない。複数回借りた履歴や返却状況の管理は対象外とする。

保存時の検証では、タイトル・登録日・読書状態を必須とし、状況別の日付条件は新規登録時に検証する。更新時は未発生の日付を空欄のまま許可する一方、状態変更を理由に既存日付をクリアする更新は行わない。

### 登録時の日付ルール

登録日はいずれの登録方法でも必須とし、新規登録時に当日を初期値にする。状況の選択に応じて借用日・購入日の入力欄を切り替える。

| 新規登録方法 | 登録日 | 借用日 | 購入日 |
| --- | --- | --- | --- |
| 購入候補 | 必須 | 空欄 | 空欄 |
| 借用 | 必須 | 必須（初期値は当日） | 空欄 |
| 購入 | 必須 | 任意（以前借りていた場合） | 必須（初期値は当日） |

日付は初期値を登録日と同じ日にしてよい。過去の日付で登録する場合は利用者が修正できる。日付の初期値と入力切り替えは新規登録画面の動作であり、登録後は既存の日付を保持したまま追加・修正できる。

### 登録後の更新

- 候補から借りた場合は `borrowedOn` を設定する。導出状況は「借用記録あり・未購入」とする。
- 借用中の本を購入した場合は `purchasedOn` を設定し、既存の `borrowedOn` は保持する。3つの登録・借用・購入日をすべて記録できる。
- 購入候補フラグ、一言メモ、読了日は常に任意とする。
- 読書状態は新規登録時に未読とし、利用者が任意のタイミングで変更する。読書状態の変更で日付や他の項目を自動消去しない。
- `readOn` は状態変更に伴って自動設定・消去せず、任意入力とする。
- 一度記録した借用日・購入日は状況変更によって消去しない。誤入力を直す場合は日付を明示的に修正する。

初期リリースの読書状態は「未読」「読書中」「読了」とする。中断・再読などは必要になった時点で拡張する。

## 開発カンバン

要件と作業は [カンバンボード](./doc/usage-plan.json) で管理する。機能を親カード、要件整理・実装・検証を子タスクとして分け、作業状態は次の列で管理する。

- 未整理
- 着手可能
- 進行中
- 保留・要確認
- 完了

現時点で保留・要確認にある仕様判断:

- ISBN検索元と検索失敗時の入力方法
- 書影の取得・保存方法
- 一括削除の対象選択と誤操作防止

読書状態と所持状況・日付の関係は本仕様で定義済み。ボードにはデータモデル、登録フォーム、更新時に既存日付を維持する処理の実装タスクを登録する。ボードの状態・カード一覧が最新の作業状況を示す。
